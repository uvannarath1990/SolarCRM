# KRE CRM — Session Handoff (2026-09-20)

Everything below is **deployed to production** (hPanel) and lint-clean. Nothing was committed to git — deploys were done by rsync only.

## 1. Environment / how to work on this

| Thing | Value |
|---|---|
| Stack | Hand-rolled PHP 8.1 MVC, route table in `index.php`, PDO, Bootstrap 5, `apiFetch()` |
| SSH host | see your own deploy notes — kept out of this repo |
| Web root | `<WEBROOT>/employee/` |
| DB | MariaDB 11.8 — credentials live only in `config/db.php`, which is git-ignored |
| Lint | No local PHP — run `php -l` on the server |

Deploy:

```bash
rsync -avz --checksum --relative -e "ssh -i <SSH_KEY> -p <PORT>" <files> <USER>@<HOST>:<WEBROOT>/employee/
```

**Conventions worth knowing**

- `jsonError()` returns `{error}` — JS must read `res.error`, not `res.message`.
- Shared helpers: `applyLeadStage()` (`includes/workflow.php`), `canAccessLead()` / `roleCan()` / `assetUrl()` (`includes/functions.php`), `auditTaskCreate()` / `auditConfig()` (`includes/audit.php`).
- `assetUrl()` does mtime cache-busting — use it for any JS/CSS or the browser will serve stale files.
- `leads.updated_at` is `ON UPDATE CURRENT_TIMESTAMP`, and the "won this month" KPI depends on it. Anything that touches leads in bulk will corrupt that KPI.
- Testing pattern: CLI harness on the server with a faked `$_SESSION` / `$_POST`. Use disposable `ZZ_`-prefixed test leads and delete them afterwards.

## 3. Last change: Next Follow-up is now read-only

The user originally asked for a formula field (next follow-up = nearest open task's due date), then said: **"for now just make the field non editable."** Only the non-editable part was done.

Removed:
- `controllers/LeadsController.php` — `next_followup_date` out of the inlineEdit whitelist; syncFollowUpTask block removed; bulk action removed from the actions list, the validation branch and the apply branch.
- `controllers/LeadDetailController.php` — `next_followup_date` out of `$fields`; syncFollowUpTask call removed.
- `includes/workflow.php` — `syncFollowUpTask()` deleted (no references remain).
- `views/leads/list.php` — bulk "Set follow-up date" option, its date input and hint removed.

Changed:
- `views/leads/detail.php` — the date input is now a read-only display: lock icon, the date or "—", and "· overdue" in red for open leads.

**Kept deliberately:** `controllers/WorkflowController.php` still writes the date on the "Still Following Up" outcome. That is the system setting it, not a user typing it.

Verified server-side against lead 826: inlineEdit → `{"error":"Invalid request."}`, bulkUpdate → `{"error":"Unknown bulk action."}`, date unchanged (2026-09-30). Leads list JS passed a syntax check.

**No trigger and no backfill were applied.** Existing data is untouched — all 814 leads keep their current dates, including 187 hand-typed ones with no open task behind them. If the formula approach is revisited: 551 of 814 leads would change, and the trigger needs an `updated_at` guard (otherwise it bumps the timestamp and breaks the won-this-month KPI) plus a backup snapshot first.
